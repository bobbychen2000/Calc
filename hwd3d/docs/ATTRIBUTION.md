# Data sources and required attributions (Hayward Live 3D, KHWD)

Which third-party data the committed hwd3d files contain or were derived from, the terms that apply, and the notice
each one requires. The structure follows `sfo3d/docs/ATTRIBUTION.md` @ a967f9b. Quotes marked "read 2026-11-12" were
fetched from the URL given on that day; other quotes are marked with where they come from. This is not legal advice;
the owner decides.

**Open owner decisions.** The ones that already exist are in `docs/PLAN.md` §6:
- Q1 (LADD): default D1 applies, so no committed file holds a per-aircraft identity.
- Q2 (LiveATC terms): unread.
- The FAA aircraft registry: blocked (HTTP 403). The owner downloads `ReleasableAircraft.zip` by hand (see `docs/phase1_data_report.md` §6).

Added by the Phase 1 review (2026-11-12); details in `docs/phase1_data_report.md` §6:
- **Per-event ADS-B rows (extends Q1).** The committed ADS-B files hold one row per stay, signal start / end and run-up stop. Each row has an exact type designator but no identity and no time. 40 of the 148 stay rows come from LADD-flagged aircraft, and 4 of those have a type that occurs only once among the stays. Interim measures: exact stay durations removed (bucket only); run-up stop durations rounded to 10 s. Options for the owner: coarsen rare types to a class, commit only spot-level aggregates, or accept as is.
- **adsb.lol terms page.** The bare host `https://adsb.lol/docs/...` answered HTTP 403 and the `www.` host answered 200. Is `www.adsb.lol` the site's normal public URL, or did reading it work around a refusal? Until the owner answers, the two adsb.lol quotes below are marked accordingly.
- **OSM contributor metadata.** The committed extract no longer holds contributor names or ids (see the OSM row). sfo3d's committed extracts still do (`docs/requests_to_sfo3d.md` R5).
