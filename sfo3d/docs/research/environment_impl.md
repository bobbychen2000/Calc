### 0.2 Relay weather (spec §3.2–3.3) — relay smoke test

`sfo_live_server.py` (only the METAR/TAF class, `/api/ping`, the payload head and one line in `main`):

- `dataNow` (ms) = the data clock: the recording's time in replay (`Clock.to_src`), wall time live; in `/api/ping`, in
  every ADS-B payload head (`Hub._merge`) and as `X-Data-Now` on `/api/metar`.
- `/api/metar?ids=KSFO[&format=json]`: one upstream request `metar?ids=KSFO&format=json&hours=3` serves both formats
  (raw = the `rawOb` lines, newest first). Conditional (`If-None-Match` with the ETag; 304 keeps the body), TTL 60 s
  from hh:59 to hh:03 and 300 s otherwise, never below the upstream `cache-control: max-age` (60 s, **M** headers
  2026-11-05); on demand only (the app asks every 60 s; no polling without a client: conserves the provider). Upstream
  errors keep the last good list (`X-Wx-Upstream-Error`); the app flags staleness itself (> 90 min of data time).
- `/api/taf[?format=json]`: `taf?ids=KSFO&format=json` (issueTime, validTimeFrom/To, rawTAF); each newly issued TAF is
  saved once to `refs/cache/replay/wx/taf_ksfo_<issue>Z.json` so later replays can show the TAF in force.
- Replay: METARs observed at or before the replay time only (all of the last 3 h, newest first; 90-min rule kept),
  TAFs issued at or before and valid at the replay time; otherwise 502 with the reason (never today's weather).
- Browser fallback removed: `js/live/feed.js fetchMetar` now needs the relay URL (aviationweather.gov sends no CORS
  header, **V**) and returns the relay's JSON list; `fetchTaf` added.

**Relay smoke test: PASS 14/14** (`python3 tools/env/test_relay_wx.py`, offline, fake upstream serving the real AWC

### 1.3 Both renderers take sun / time / weather from EnvState (spec §9.1 item 1, §3.2)

Both renderers are driven by `js/live/app.js applyEnv` (live.html → `js/renderer.js`; live3.html → the import map
swaps in `js/three/renderer3.js`, whose `setupSky(env)` / `extraCommon.uNight` / sprites read the same values), so one
small local edit wires both:

- `js/env/app_env.js` `AppEnv` (data clock + reports + EnvState + QA overlays) replaces `parseMetar`, `lightDate` (the
  hard-coded `pdt + 7` presets) and `solarPosition`: the sun direction is `EnvState.sun.dir` (ephemeris, apparent),
  the light-mode menu sets `DataClock.setLightMode` (sunEvents instants on the local date; `SFO.setLight('dawn')` works,
  the menu itself (ui.js, not this track's file) still lists Real / Day / Dusk / Night), `metar` is the compact view of
  the CURRENT report by data clock, `R.envState` carries the full EnvState for later steps.
- The renderers' night heuristics (`nightF`, `dark`, the night ambient floor, the exposure ramp: unsourced, replaced by
  C171 + EV100 in step 3 / A-EXP) now key on the GEOMETRIC elevation `sun.elTrue`. Finding (**M**): `ephemeris.js`
  clamps Bennett refraction at its −1° value below −1°, so the apparent `sun.el` of a Sun below the horizon is
  elTrue + 0.65° (its tests compare refracted elevations only above 0°; the preset table's below-horizon "Sun el" values
  include the offset, e.g. dawn −3.98° = true −4.63°). Keying the heuristics on apparent el would have moved night
  onset ~4 min later; twilight is defined on the geometric elevation (USNO). Step 3 should feed the sky model the
  geometric direction below −1°.
- Relay: `/api/metar?ids=KSFO&format=json` every 60 s (was 10 min) and `/api/taf` every 10 min; `dataNow` from
  `/api/ping` and every payload feeds the replay clock (`feed.js parsePayload` / `StreamFeed.emit` pass it through).
  `fetchMetar` also accepts raw lines (older relays, the `livetest.mjs` mock).
- QA: `?qa=env` HUD (`#qa-env`, every value with its tag, METAR + age + stale/forecast, the open-question defaults);
  `?qa=prov` draws all 3,633 fixture faces tinted by provenance on top of the current lights (day and night); the UI
  clock shows "env <time> (preset) ≠ traffic" whenever the environment time is overridden.
- Old vs new Sun (**M**, `sun_cmp.mjs` in the scratchpad): at the 14 preset instants the old `solarPosition`
  (geometric, NOAA formulae) and the new apparent elevation differ by 0.01–0.04° by day and 0.64° below the horizon
  (the clamp above), azimuth ≤ 0.01°. Apparent sunset 23 Sep 2026 (Sun centre on the horizon): new 19:03:15 PDT, old
  19:00:24 PDT (old 2.85 min early: the spec's "2.9 min"); USNO-definition sunset (−50′ geometric) 19:04:33 PDT
  (USNO table 19:05). The spec's A-SUN render criterion ("disc centre on the horizon within 1 min of apparent sunset
  19:04:33") mixes the two definitions: 19:04:33 is the −50′ instant, when the apparent centre is already 0.27° below the
  horizon by Bennett; the render test must use 19:03:15 for "centre on the horizon" (open point for the step-3 renders).
